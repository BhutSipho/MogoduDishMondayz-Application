# Mogodu Monday Specials

Create a modern, responsive web application called Mogodu Monday for a food business that specialises in mogodu (tripe) dishes.

The application should be a simple, presentable MVP that demonstrates the ability to build an application using AI-assisted development. Keep the project practical and avoid unnecessary complexity.

Core Purpose

The application should allow customers to view Mogodu Monday offerings, see specials, place orders, track their orders, and interact with the business through a simple and easy-to-use interface.

Required Features

Home Page

Introduce Mogodu Monday and the food offering.

Clearly display the current or featured specials.

Include clear calls-to-action for viewing the menu and placing an order.

Orders

Allow users to select food items and quantities.

Allow users to place an order through a simple ordering flow.

Display an order summary before submission.

Provide basic order confirmation after an order is placed.

Order Tracking

Allow a customer to view the status of an order.

Use simple statuses such as:

Order Received

Preparing

Ready

Completed

Specials

Create a section where Mogodu Monday specials can be displayed.

Make the specials visually prominent and easy to understand.

Calendar View

Include a simple calendar view showing relevant Mogodu Monday dates, specials, or scheduled offerings.

Keep the calendar easy to understand and mobile-friendly.

Notifications

Include a basic notification area or notification system that can communicate relevant updates such as order status changes and specials.

Keep this practical for an MVP rather than implementing complex push-notification infrastructure.

Analytics

Include a simple analytics/dashboard section showing basic order information.

Include analytics covering the last six months, as required by the project brief.

Use clear charts or summary figures where appropriate.

Design Requirements

Mobile-friendly design.

Fully responsive across mobile, tablet and desktop.

Modern and attractive food-business interface.

Easy navigation.

Clear typography and readable content.

Strong visual presentation suitable for a food brand.

Use a warm, appetising visual style while keeping the interface professional.

Make buttons, forms, menus and ordering actions clear and accessible.

Avoid unnecessary visual complexity.

Application Structure

Create a clean structure with appropriate pages/components for the main functionality, such as:

Home

Menu / Specials

Order

Order Tracking

Calendar

Notifications

Analytics

Use reusable components where appropriate and keep the project organised so that it can be maintained and improved.

Functionality

Make sure the main user flows work rather than creating static screens only. In particular:

Browse → Select food → Place order → Receive confirmation → Track order

The application should handle basic form validation and provide clear feedback to the user when actions succeed or fail.

Do not use unnecessary placeholder functionality. Where a full production service such as real payment processing or push notifications would require external services, keep the implementation at a sensible MVP level and make the limitation clear in the application structure.

Quality Requirements

Before considering the initial build complete:

Make sure the application loads correctly.

Make sure navigation links work.

Make sure the main ordering flow works.

Make sure order tracking works.

Make sure the calendar is functional.

Make sure the specials are displayed correctly.

Make sure notifications/updates are usable.

Make sure the six-month analytics section is functional.

Check the application on mobile and desktop layouts.

Fix obvious UI, responsiveness and functionality issues.

Keep the design presentable and consistent.

Build this as a practical assessment project rather than an overly complex production platform. Prioritise working features, usability, clean structure and a polished presentation.
